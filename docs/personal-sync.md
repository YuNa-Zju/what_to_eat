# 个人餐簿同步

页头的云朵图标打开「随身餐簿」。点击「获取我的同步码」，再在另一台设备访问同一部署的网站、打开相同入口并输入同步码，即可连接同一份个人餐簿。

## 同步内容

- 「我自己吃」的用餐记录：饭店 ID、日期、评价、总花费、创建时间及已发布分享的关联 ID。
- 个人推荐窗口长度及最近一次发布使用的昵称（包括匿名选择）。

聚餐记录、饭店目录和公开分享原本就在服务器，不需要同步码。文字草稿、未发布照片、定位、教程状态和页面筛选不参与同步。同步个人记录不会把它们发布到聚餐历史或大家的动态。

## 合并与离线

首次连接时合并两端不同 ID 的记录，同 ID 的记录及窗口、昵称采用已有云端餐簿的值。本机连接前的数据快照保存在浏览器的 `what-to-eat:before-sync:v1`，用于异常恢复。

之后每次本机修改会在约 600 毫秒后同步；页面可见时每 15 秒检查一次其他设备的修改，重新联网或回到页面时也检查。可在餐簿窗口点击「立即同步」。断网时继续使用本地记录，恢复网络再上传。

同步使用服务器版本号与三方合并：不同记录、同一记录的不同字段可并存；同一字段同时更改时，以后成功合并的本机修改为准。删除与编辑冲突时删除优先，避免离线设备恢复已删除记录。以记录 ID 去重，不会把同一天同一家饭店的两次真实用餐误合为一顿。同步响应期间产生的新修改保留并继续发送。

「断开此设备」保留本机当前记录，不会删除云端餐簿或断开其他设备。重新连接按首次连接处理，会重新合入本机保留的记录；如果不希望保留旧副本，应先在连接状态下删除对应记录。该功能是小团体的简单同步，不提供账号找回、历史版本或回收站。

## 部署与数据

迁移 `0008_personal_sync.sql` 自动创建个人餐簿表，升级前备份完整 `DATA_DIR`。同步数据位于同一个 SQLite 数据库，不需要外部同步服务或第三方账号；不同服务器的同步码不互通。

同步码是访问这份餐簿的凭据，持有码的人可以读写它。服务端生成 UUID v4 随机码，只存 SHA-256 摘要；客户端通过 `X-Sync-Code` 请求头发送，不放在 URL 中。生产环境必须使用 HTTPS。记录以普通数据存储在服务器，**不是端到端加密**，服务器管理者可访问数据库。

API 响应禁止缓存；版本冲突返回 409，不允许旧版本直接覆盖新数据。每份餐簿最多 10,000 条记录、昵称 40 字，接口请求上限 2 MiB；同一访客每天最多创建 10 个同步码。同步不使用高德服务，不增加高德调用量。
