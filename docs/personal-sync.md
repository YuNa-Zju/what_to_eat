# 个人餐簿同步

页头的云朵图标打开「随身餐簿」。点击「获取我的同步码」，再在另一台设备访问同一部署的网站、打开相同入口并输入同步码，即可连接同一份个人餐簿。

## 同步内容

- 「我自己吃」的用餐记录：饭店 ID、日期、评价、总花费、创建时间及已发布分享的关联 ID。
- 个人推荐窗口长度及最近一次发布使用的昵称（包括匿名选择）。

聚餐记录、饭店目录和公开分享原本就在服务器，不需要同步码。文字草稿、未发布照片、定位、教程状态和页面筛选不参与同步。同步个人记录不会把它们发布到聚餐历史或大家的动态。

## 合并与离线

首次连接时合并两端不同 ID 的记录，同 ID 的记录及窗口、昵称采用已有云端餐簿的值。本机连接前的数据快照保存在浏览器 IndexedDB 中的 `what-to-eat:before-sync:v1` 项，随个人数据一起保存，用于异常恢复。

之后每次本机修改会在约 600 毫秒后同步；页面可见时每 15 秒检查一次其他设备的修改，重新联网或回到页面时也检查。检查时携带本机版本，云端没有变化则返回空响应，不重复下载整份餐簿。可在餐簿窗口点击「立即同步」。断网时继续使用本地记录，恢复网络再上传。

同步使用服务器版本号与三方合并：不同记录、同一记录的不同字段可并存；同一字段同时更改时，以后成功合并的本机修改为准。删除与编辑冲突时删除优先，避免离线设备恢复已删除记录。以记录 ID 去重，不会把同一天同一家饭店的两次真实用餐误合为一顿。同步响应期间产生的新修改保留并继续发送。

每次待发送的修改使用独立操作编号，发送前将操作编号、完整请求和当时的本机内容一起持久保存为 `pendingWrite`。若服务器已保存但响应丢失，重试只确认原操作，不会把旧内容重新覆盖到后来其他设备的修改上；确认后继续获取最新餐簿并合并。网络错误、超时或刷新页面后继续使用这份待确认请求，不能直接生成新编号；收到明确的版本冲突后，重新合并并创建新操作。

「断开此设备」保留本机当前记录，不会删除云端餐簿或断开其他设备。重新连接按首次连接处理，会重新合入本机保留的记录；如果不希望保留旧副本，应先在连接状态下删除对应记录。该功能是小团体的简单同步，不提供账号找回、历史版本或回收站。

## 浏览器本地保存

IndexedDB 是个人数据的主存储。数据库 `what-to-eat-sync` 的 `checkpoint` 存储区以一个 `state` 条目保存个人用餐、窗口、昵称、同步设置及连接前快照。普通编辑和同步结果都在同一个读写事务中读取最新内容并原子提交；网络请求在事务外执行，多个标签页也通过该事务串行保存，包括普通 HTTP 环境。

首次使用时导入原有 localStorage 数据。localStorage 随后仅作为兼容缓存；缓存写入失败不会撤销已成功提交的 IndexedDB 数据。升级后应刷新所有已打开的旧版标签页，再继续编辑个人记录，以免旧页面继续只修改旧存储。

新版本通过 IndexedDB 事务同时提交记录、昵称和同步设置，不再创建 `pendingApply` 恢复日志。升级时仅兼容旧版直接保存整份内容的 `pendingApply`：若它与当前个人数据一致，只清除旧标记；若不一致，旧格式没有足够的合并依据，系统保留数据、暂停同步并提示恢复，不会自动覆盖当前记录。此时选择断开，程序会先把旧同步设置及当前个人数据保存到 `what-to-eat:sync-migration:v1` 迁移备份，再清除连接；当前个人记录保留，可检查备份后重新连接。迁移备份与连接前快照都保存在 IndexedDB，并尝试镜像到 localStorage。

待发送请求的 `pendingWrite` 与旧恢复日志用途不同，仍需持久保存，以便在响应丢失或刷新页面后用相同操作编号继续确认。

## 部署与数据

迁移 `0008_personal_sync.sql` 自动创建个人餐簿表，`0009_personal_sync_operations.sql` 创建幂等操作回执表，升级前备份完整 `DATA_DIR`。同步数据位于同一个 SQLite 数据库，不需要外部同步服务或第三方账号；不同服务器的同步码不互通。

同步码是访问这份餐簿的凭据，持有码的人可以读写它。服务端生成 UUID v4 随机码，只存 SHA-256 摘要；客户端通过 `X-Sync-Code` 请求头发送，不放在 URL 中。建议生产环境使用 HTTPS 保护传输中的同步码和餐簿；普通 HTTP 环境也支持同步功能。记录以普通数据存储在服务器，**不是端到端加密**，服务器管理者可访问数据库。

回执只保存同步码摘要、操作编号、请求摘要和确认版本，不保存第二份用餐快照。回执与餐簿更新在同一事务内提交，并使用与共享数据写入相同的服务写锁。回执随数据库一起备份；为支持长期离线重试，不按时间自动删除回执。

API 响应禁止缓存，包括版本未变化时的 204；版本冲突返回 409，不允许旧版本直接覆盖新数据。每份餐簿最多 10,000 条记录、昵称 40 字，接口请求上限 2 MiB；同一访客每天最多创建 10 个同步码。同步不使用高德服务，不增加高德调用量。
