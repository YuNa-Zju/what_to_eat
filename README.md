# 今天吃什么

少一点纠结，多一点好好吃饭。一个适合朋友小团体共同使用的用餐选择与分享网页。

**线上使用需要更新程序、静态资源和数据库迁移。** 已发布版本的检查范围见 [验证记录](docs/verification.md)，各版本更新见 [发布记录](docs/releases.md)。

## 可以做什么

- 首次访问自动开启高亮操作引导，逐步定位模式切换、抽选、窗口、记录、分享、搜索、历史和管理；右上角可随时重看，关闭后在当前浏览器记住。教程中可以操作真实控件，打开表单后暂停、关闭后继续，不会自动提交记录或覆盖已有草稿。
- 共用饭店名单，初始包含 30 家；任何访问者都能新增和修改资料，不再区分候选／不候选状态。
- 在“我们聚餐”和“我自己吃”之间切换，分别维护云端历史和浏览器本地历史。个人推荐独立计算两边的窗口并取并集避开；喜好只使用当前模式的评价与频率。
- 默认避开最近 **5 家不同饭店**，从剩余饭店中按喜好概率推荐；也可以手动记一顿、补记日期、编辑或删除记录。
- 窗口长度可调整为 1–100。重复吃同一家只占一个位置，完整历史一直保留。
- “记一顿”和“写分享”使用统一表单，可只记录用餐、记录并分享或仅发布分享；花费可选，按人民币记录本次总额，并显示在历史和分享中。
- 每顿可评价“喜欢／一般／不喜欢”；以评价为主、用餐频率为辅微调推荐概率，新店保留探索机会。
- 用餐账本按日期分组，筛选和近两周用餐柱状图按需展开，金额、评价、关联分享集中在一行。
- 选餐页可主动开启“考虑距离”，按当前位置到饭店的直线距离温和调整概率；未标位置的饭店保持原权重。位置仅保留在本次页面内，15 分钟后失效。
- 匿名或填写昵称发布 Markdown 分享，支持标题、列表、引用、链接、代码和表格。成功发布后在本机记住昵称，下次自动填入；草稿优先，清空后发布会记住匿名选择。
- 分享在桌面按双列瀑布流展示，手机为单列，支持关键词、饭店、昵称、用餐日期组合筛选，以及发布时间、用餐日期和点赞数排序。点击用餐记录可查看其关联分享。
- 饭店选择支持中文片段模糊搜索；日期、选择框和选中状态统一使用自定义样式。
- 手机编辑器提供格式工具栏、编辑/预览切换及相册多选；桌面提供并排预览。布局适配手机、平板与桌面。
- 菜单式奶油纸色界面，自托管分片霞鹜文楷、纯色底面与疏落碎金、手绘面碗和桌面侧边书签；手机保留底部导航。顶部栏固定，首页按可用高度安排为一屏，其他菜单在独立阅读区域内滚动；面碗首次出现时逐笔绘制。按目录顺序切页时，桌面旧页从底边向上掀开、手机旧页从右向左翻过，返回则反向翻回；约 0.85 秒完成，保留各页阅读位置。不支持 View Transitions 的浏览器使用柔和淡出淡入。抽选先确定结果，再用 1.6 秒连续滚动停在同一名字节点；系统减少动态效果设置下直接切换。
- 明暗主题自动跟随系统，切换时立即生效；暗色使用暖炭灰底色与柔和琥珀色，包含编辑器、弹窗、图表和插画。
- 每帖可上传 6 张照片，支持 JPEG、PNG、WebP，每张输入最多 10 MiB、2500 万像素。选图后浏览器压缩并提前上传，最长边 1280 像素、目标 300 KiB；服务器再次验证并按需转换为 WebP，保留透明背景与正确方向。
- 多图默认显示一张封面，右下角显示剩余张数；点击打开支持方向键、滑动与缩略图的画廊。
- 编辑分享可修改昵称、正文和照片；未绑定用餐的分享也可修改饭店、日期和花费；共享绑定项在用餐历史中统一修改，并同步到关联分享。
- 支持点赞、点踩、取消投票。任何访问者都能修改或删除分享，无需账号。
- MD5 查找重复图片，再核对文件内容；UUID 文件名与数据库引用关系共同管理照片，最后一个引用删除后才清理文件。

- 点击饭店目录条目直接打开完整可编辑资料，封面、名称、地址与地图位置在同一窗口查看和保存；地图按需加载，可搜索地点、点击或拖动标记。资料接口兼容旧客户端，照片与分享复用压缩、去重及引用清理。
- 点赞、用餐与饭店编辑采用实体级乐观更新，轮询保留待提交修改；失败只回滚该操作，可在原表单或重试入口再次提交。

地图配置见 [高德接入说明](docs/maps.md)。未配置时仍可使用文字、照片及其他全部功能。

## 技术与目录

前端：React、TypeScript、Vite、Tailwind CSS 4、shadcn/ui。Markdown 使用 `react-markdown`、`remark-gfm` 和 `rehype-sanitize`。

后端：Rust、Axum、tower-http、SQLx、SQLite。Rust 同时提供静态网页、API 和图片。Node 只用于前端开发与构建，生产环境无需 Node 服务或单独的数据库服务。

```text
frontend/       React 网页、shadcn/ui 组件、前端测试
src/            Rust API、图片处理、数据库初始化
migrations/     SQLite 迁移
resources/      初始饭店名单
tests/          Rust 接口及图片生命周期测试
deploy/         systemd、Nginx 配置示例
docs/           部署、接口、Gitflow 和验证说明
data/           运行时生成，不进入 Git
```

## 以后如何构建和运行

构建环境需要 Rust 稳定工具链、C 编译工具链、Node.js 22.12+ 或兼容的更新 LTS，以及 npm。生产环境的 release 编译和部署仍需在目标平台执行。

```sh
cd frontend
npm ci
npm run build
cd ..
cargo build --release --locked
./target/release/what-to-eat
```

默认访问 `http://127.0.0.1:3000`。首次启动自动创建数据库、执行迁移并加入初始饭店。详细操作见 [部署说明](docs/deployment.md)。

## 开发

两个终端分别启动后端和 Vite：

```sh
# 仓库根目录。开发网页应访问 Vite 的 5173 端口。
STATIC_DIR=frontend cargo run
```

```sh
cd frontend
npm ci
npm run dev
```

访问 `http://127.0.0.1:5173`，Vite 将 `/api`、`/media` 和 `/_AMapService` 转发给 Rust。开发时的 `STATIC_DIR=frontend` 仅用于启动 API 服务，TSX 和样式由 Vite 处理；生产环境改为构建后的 `frontend/dist`。

## 使用约定

- 这是共同维护的小团体空间，没有登录、管理员或内容所有权限制；昵称只用于展示。
- 点赞身份保存在浏览器 Cookie 中，清除 Cookie 或换设备会成为新的匿名身份。
- 本地历史、窗口设置、新帖文字草稿、最近发布昵称及教程已看状态保存在当前浏览器；清除网站数据会清除这些内容。草稿不包含照片，编辑已有分享不会改写默认昵称。教程内打开的表单不读取或保存草稿，手动提交仍会正常保存用餐或分享。
- 用餐历史按用餐日期排序，同日按录入时间排序；本地日期使用访问者当前时区。
- “写分享”默认同时记入当前范围的用餐历史，可改为仅分享；“记一顿”默认只记用餐，可开启分享。草稿恢复时保留原选择，从已有历史补发分享不会重复记账。删除帖子不删除用餐历史。
- Markdown 原始 HTML 不执行，外部图片语法只显示说明文字；照片通过上传附件展示，以统一处理存储、去重和删除。
- 所有饭店均可参与推荐，最近用餐窗口仍会临时排除饭店；旧的停用标记不再影响显示、推荐或记饭，历史和分享保留。
- 每 30 秒及页面重新获得焦点时同步共享内容。多人同时编辑同一条内容，以最后一次成功保存为准。
- 服务设计为**单进程、单实例**，SQLite 和照片目录由同一个 Rust 服务管理。
